# Getting Started

## Install

```bash
composer install
cd frontend && npm install && cd ..
```

Fetch the RoadRunner binary using the official installer that ships as a
`require-dev` dependency:

```bash
vendor/bin/rr get
```

This is the real, upstream-documented way to get RoadRunner (via
`spiral/roadrunner-cli`) — not a custom downloader. Manual alternative:
download `rr`/`rr.exe` from
https://github.com/roadrunner-server/roadrunner/releases, place it in
the project root, `chmod +x rr` on Linux/macOS.

## Run

```bash
php spinx migrate
php spinx serve
```

Visit:
- `http://localhost:8080/` — the Vue reference page (directives + one
  hydrated island)
- `http://localhost:8080/todos` — the raw HTML reference page (zero
  JavaScript framework)
- `http://localhost:8080/health` — a JSON health check that also proves
  the ORM/migrations pipeline (logs a row on every hit)

For the React reference implementation, see
[templating.md](templating.md#the-react-reference-implementation).

## Your first module

```bash
php spinx make:module Orders
php spinx make:entity Orders Order
php spinx make:model Orders Order
php spinx make:repository Orders Order
php spinx make:service Orders PlaceOrder
php spinx make:controller Orders ListOrders
php spinx make:migration Orders create_orders_table
```

Each generator prints exactly what it created. `make:controller`,
`make:service`, and `make:repository` also print a snippet to paste into
`app/Modules/Orders/module.php` — routes and DI bindings are never
auto-inserted, since that file is real PHP a developer may have
hand-tuned (see [Architecture](architecture.md) for why).

Then:

```bash
php spinx migrate
```

## Where things live

```
app/Modules/<Name>/          Your application code — see Architecture
config/services.php          Framework-level DI only, rarely touched
resources/views/             Global .spinx.html templates
frontend/                    Vue (default) frontend + islands
examples/react-frontend/     React alternative — see templating.md
tools/desktop-preview/       Native desktop preview shell (Go)
tools/mobile-shell/          Mobile shell foundation (Go bridge)
mobile/                      Generated by `spinx build:mobile` (gitignored)
storage/                     Compiled caches, SQLite DB (gitignored)
```

Next: [Architecture](architecture.md) to understand why `app/Modules` is
structured the way it is, or jump straight to whichever guide matches
what you're building.
